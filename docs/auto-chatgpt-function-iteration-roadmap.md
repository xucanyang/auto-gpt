# Auto ChatGPT 功能迭代与运营闭环方案

更新时间：2026-06-07

## 1. 当前定位

当前项目已经从历史上的泛平台注册工具，演进为 ChatGPT 账号全生命周期运营后台。核心链路是：

1. 配置邮箱、验证码、代理、Solver、支付、外部同步。
2. 批量注册 ChatGPT 账号。
3. 管理账号池、账号状态、订阅状态和 Auth 状态。
4. 生成订阅链接，执行 GoPay 或外部支付。
5. 补抓 Auth，验证订阅状态。
6. 上传 CPA、Sub2API、CodexProxy、Team Manager 等下游系统。
7. 维护邮箱池、iCloud HME、TempMail、手机号池、代理池。
8. 通过自动流水线持续补货、支付、补抓和归档。

## 2. 当前功能地图

| 模块 | 当前能力 | 闭环情况 |
| --- | --- | --- |
| 仪表盘 | 账号总数、平台分布、状态分布 | 已补充运行资源健康 MVP |
| ChatGPT 账号 | 列表、筛选、排序、详情、导入导出、批量操作、状态同步 | 功能强，但状态语义和下一步建议仍需收束 |
| 注册任务 | 批量注册、执行器选择、邮箱服务、验证码、实时日志、停止/跳过 | 任务控制可用，失败归因和配置模板待完善 |
| 支付与 GoPay | 支付链接、GoPay batch、OTP/PIN、国家配置、手机号池联动 | 链路深，支付作业中心待独立 |
| Auth 补抓 | 单账号/批量补抓、Browser Auth 兜底 | 需要工作台和账号时间线 |
| 邮箱资源 | 多邮箱服务、iCloud HME、TempMail 归档、自动补池/删除 | 能用，缺统一资源视图 |
| 手机号池 | 导入、状态、容量、绑定邮箱、拒绝号段、恢复禁用删除 | 较完整，缺质量评分和按号段/host 分析 |
| 代理池 | 导入、启停、检测、冷却、首页健康 | 需要质量分层和用途隔离 |
| 自动流水线 | 注册补货、支付批次、Auth 补抓、队列和日志 | 接近完整，缺安全阈值和自动暂停策略 |
| 外部订阅 API | claim、release、result、延迟验证和重启恢复 | API 闭环有，运营页面缺失 |
| 配置 | 大量全局配置、服务启动停止、GoPay OTP 配置 | 配置预检、secret 展示策略、字段 schema 待完善 |

## 3. 第一阶段需求池

### 3.1 基础功能补齐

- 统一账号生命周期状态字典。
- 统一错误码与失败归因。
- 任务配置模板和历史配置复用。
- 配置预检与连接测试。
- 运行资源健康中心。

### 3.2 核心流程优化

- 账号列表和详情展示生命周期阶段。
- 账号详情展示下一步建议、可执行动作和禁止动作。
- 批量操作展示明确作用范围。
- 批量高风险操作进入确认流程。
- TaskLogPanel 展示停止中、重连中、完成后刷新入口。

### 3.3 功能闭环完善

- 失败处理中心。
- 外部订阅 claim 管理页。
- 支付作业中心。
- Auth 补抓工作台。
- 账号时间线和资源消耗记录。

### 3.4 管理后台与配置能力

- 配置字段 schema 化。
- Secret 字段默认脱敏展示。
- 外部集成健康检查。
- iCloud HME 别名池、自动补池、清理删除拆分。
- 代理、手机号、邮箱资源统一预检。

### 3.5 权限与安全

- API token scope 管理。
- 操作审计。
- 危险操作二次确认。
- 无后台密码且公网监听时强警告。

### 3.6 数据统计与反馈

- 注册成功率、失败原因、平均耗时。
- 支付成功率、GoPay OTP/PIN 成功率。
- Auth 补抓成功率。
- 邮箱、手机号、代理资源消耗统计。
- 账号状态冲突巡检。

## 4. 本轮已落地的 MVP

### 4.1 运行资源健康接口

新增：

```text
GET /api/system/health
```

该接口只读聚合：

- 账号池
- 代理池
- 手机号池
- Turnstile Solver
- 后台调度器
- 自动流水线
- iCloud HME 自动补池
- iCloud HME 自动删除
- TempMail 归档清理

返回结构：

```json
{
  "generated_at": "2026-06-07T00:00:00Z",
  "summary": {
    "healthy": 1,
    "warning": 2,
    "error": 0,
    "unknown": 1,
    "total": 4
  },
  "resources": [
    {
      "key": "phone_pool",
      "title": "手机号池",
      "status": "healthy",
      "message": "可用 10 个，剩余容量 30",
      "metrics": {},
      "action_path": "/phone-pool",
      "details": {}
    }
  ]
}
```

### 4.2 仪表盘资源健康区

仪表盘现在除了账号统计，还展示运行资源健康。异常资源会给出状态、说明和处理入口，用户不需要先启动任务再从失败日志里倒推资源问题。

### 4.3 仪表盘统计错误态与空态

账号统计接口失败时，仪表盘现在会显示页面内错误提示并保留旧数据。平台分布、状态分布为空时显示明确空态，避免用户把“没有数据”和“接口失败”混在一起。

### 4.4 Solver 停止兜底

Solver 关闭时如果子进程 5 秒内不退出，会自动 kill 并等待结束，避免后端 shutdown 被僵住。
