# AGENTS.md

## 项目工作流

本项目采用 Spec-driven 开发流程。

在实现任何功能之前，必须先阅读以下文件：

1. `requirements.md`
2. `design.md`
3. `tasks.md`

## 必须遵守的行为

- 不要实现 `requirements.md` 中没有描述的功能。
- 除非 `design.md` 明显过时，否则不要擅自修改架构设计。
- 以 `tasks.md` 作为任务执行顺序的唯一依据。
- 每次只处理一个任务。
- 在修改任何文件之前，必须先输出执行计划。
- 除非用户明确要求继续，否则必须等待用户确认后再开始实现。
- 每完成一个任务后，必须：
  - 运行相关测试、lint 或 typecheck
  - 总结修改过的文件
  - 更新 `tasks.md`，将已完成任务标记为完成
  - 说明是否还有阻塞或不明确的任务

## 执行计划格式

处理每个任务前，必须先输出：

1. 从 `tasks.md` 中选择的任务
2. 对应的 `requirements.md` 需求
3. 对应的 `design.md` 设计说明
4. 需要检查的文件
5. 可能需要修改的文件
6. 分步骤实现 checklist
7. 验证命令
8. 风险或假设

## 实现规则

- 修改必须尽量小，并且只围绕当前任务。
- 不要修改无关代码。
- 除非当前任务明确需要，否则不要做重构。
- 如果任务存在歧义，先说明歧义，并给出一个安全的理解方式。
- 如果测试失败，必须先修复失败，再将任务标记为完成。

## 执行模式规则

当用户说“继续下一个任务”时，表示进入执行模式，而不是只做计划。

执行模式必须按以下流程进行：

1. 读取 `requirements.md`、`design.md` 和 `tasks.md`
2. 找到 `tasks.md` 中第一个未完成任务
3. 简短输出执行计划
4. 直接开始实现，不需要再次等待用户确认
5. 每次只处理一个任务
6. 完成后运行验证命令
7. 验证通过后更新 `tasks.md`
8. 完成后停止，等待用户下一步指令

只有当用户明确说“只做计划”“不要修改文件”“先不要执行”时，才停留在 planning 阶段。
